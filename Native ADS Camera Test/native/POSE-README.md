# Native shared-rig pose candidate 0.1.7

`py -3 native/build_pose.py` builds `dist/native/native_ads_pose_0_1_7.dll` and runs the separate-process `pose_fixture.cpp`. This does not access the game. The previous 0.1.6 source and build are preserved under ignored `dist/research/native-pose-0.1.6-preserved`; the older 0.1.5 helper remains in its original files.

The existing `NADSP_*` ABI retains its 96-byte config and 80-byte stats structure from `native_ads_pose.h`. Begin returns 0 for rejection with no owned lease, 1 for armed, or 2 for an owned partial dispatch installation requiring End cleanup. Validate performs read-only binary/API, graph and normal-camera owner checks. DLL callback code remains pinned; End restores only owned writable dispatch pointers and retains reservation on cleanup failure. Legacy stats field `weapon_updates` now counts modified shared-rig calls; `zero_restores` counts native-baseline restores, which do not write zero.

Every native first-person carrier-root position and rotation call forwards its original unit, node, pointer and pose bytes. Only the position call returning to game RVA `0x1288424`, for the leased carrier UnitRef, verified node 5 and source pointer `request+0x48`, can be modified. A 16-byte aligned local copy adds X `+0.15*weight` and Z `-0.12*weight` to that call's fresh native position. Y, arbitrary W padding bits, and the source buffer remain unchanged. Finite XYZ is required. The native setter runs once for that call; no extra weapon-unit root setter runs. A 150-millisecond smoothstep blends toward zero for native ADS and toward one otherwise.

The candidate supports the captured 63-node carrier graph only. Its embedded graph getter, graph/table identities and selected node hashes/parent links must match: shared node 5 contains the weapon attachment and both arm chains; camera node 50 is its sibling under node 4. Graph mismatch refuses preflight or stops matching updates with error 15 (`GRAPH_MISMATCH`). Unreadable/nonfinite XYZ gives error 16 (`POSE_INVALID`). The weapon descriptor's 20 captured bytes and both UnitRefs' native generation/object identities remain checked. Current camera/context/request/avatar/body/weapon/controller ownership is checked on every matching update. Native aiming or controller activity sets the blend target to zero without disarming. Other block/guard flags remain invalid. Selected sight node `request+0x18` must remain nonzero; otherwise error 14 (`SIGHT_NODE_UNAVAILABLE`) stops offsets.

Other calls forward exactly. Native fading ring records legitimately reach the same unit/node/callsite with another source pointer; these calls pass through without disarming and invalidate our cached restore eligibility. A later matching owned record establishes a fresh baseline again. Foreign unit and other-node calls retain the local lease.

End and TTL restore the latest cached unmodified native 16-byte position only while the same owned type-6 request, graph and unit identities remain valid. A fresh target call at expiry forwards its current native position directly and prevents replay of an older cache. Owner/generation/graph loss or a native type-4 transition skips stale restoration. The policy lock covers each modified native setter, so cleanup cannot finish ahead of an in-flight offset. No camera transform, whole-carrier offset, body event, scope visibility operation, executable patch, permission change or thread suspension is performed.

The 24 synthetic fixture groups verify root forwarding, fresh-input arithmetic, graph/ownership guards, fading-record pass-through, ADS blending, baseline cleanup, in-flight cleanup ordering and pointer transaction failures. They establish no live image or gameplay result. Moving a parent of the attached weapon can also move muzzle world nodes; existing beam code consumes those positions. Cosmetic-only behavior and network consequences have not been established.
